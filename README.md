**输入任意两个车站（或城市），自动抓取该区间的全部车次，画成一张可视化的「运行图」。**

一个**零第三方依赖**的本地工具：横轴是时间、纵轴是车站，每趟车一条横线；支持车型 / 席别 /
发车时间 / 票价筛选、余票与「有票」高亮，以及「经某站中转」的两程联程查询。

> **没有写死的线路。** 顶栏填入「出发 / 到达」点「换线路」，就能查任意区间 ——
> 通道怎么分、车站怎么归并到城市、纵轴怎么排，**全部由数据推导**，代码里没有任何一条线路名。
> 首页默认展示的 郑州 → 常州（京沪 / 合杭 / 连镇 三条通道）只是启动时的一条示例。
>
> 实测：一条全新区间 **上海 → 杭州**（393 趟车次、零缓存）首次取数约 **20 秒**，
> 并自动分出「嘉兴 / 湖州」两条通道。

## 🚀 三步上手

1. **双击 `启动.bat`** —— 自动探测本机 Python（3.10+）、起本地服务、打开浏览器；关掉黑窗口即停止服务。
2. **顶部填「出发 / 到达」** —— 城市或车站都行（填「上海虹桥」会按上海整城处理，
   把上海 / 上海南 / 上海松江 的车次一并返回）。输入框带 3388 个站名的自动补全，打错的站会当场标红，不会白跑一趟。
3. **点「换线路」** —— 已有缓存的区间几秒出图，全新区间约 10–40 秒（首次要把每趟车的经停站抓一遍，
   之后按车次永久缓存，切回来不必重抓）。

想换乘车日期就改顶部的日期选择器，重抓即可（12306 预售期内任意日期）。

## ✨ 功能特性

- **任意区间查询**：始发 / 终到可填**任何城市或车站**，按城市解析电报码，同城各站一并纳入；
  数据按区间分目录缓存（`data/routes/<起>_<终>/`），互不干扰。
- **运行图可视化**：每趟车一条横线，横轴是时间、纵轴是车站；G / D / Z / T / K 与纯数字车次各有线型。
- **通道自动划分**：一条干线两侧常有好几条走廊（郑州→常州 就同时有京沪线、郑阜+商合杭、郑徐+连镇），
  它们的车站轴互不相同，画在同一根轴上会互相穿插。工具把每趟车的**中间城市集合**两两算
  Jaccard 相似度（≥ 0.45）后聚类，**自动分出若干条走廊**，各自一根轴 ——
  郑州→常州 分出京沪 / 合杭 / 连镇，上海→杭州 分出嘉兴 / 湖州，常州→上海 分出苏州 / 张家港。
  不依赖任何写死的线路名。通道名默认取该通道最具辨识度的中间站（如「嘉兴通道」），
  也可在 `data/channel_aliases.json` 里改成习惯的叫法（郑州→常州 已预置为京沪 / 合杭 / 连镇）。
- **站点归并（官方数据驱动）**：站名 → 城市一律查 12306 官方车站表 `station_name.js` 自带的
  「城市」字段（3388 站全覆盖；早期版本的正则只取了前两个字段，所以城市只能手写字典）。
  规则依次是：① 本路线起终点所在城市的车站一律并到端点行（武进 / 戚墅堰 / 金坛 → 常州）；
  ② 站名以官方城市名开头 → 并入该市（郑州东 → 郑州、杭州东 → 杭州）；③ 站名以同城另一个站名开头
  → 并入那个站（兰考南 → 兰考、民权北 → 民权）；④ 以 东/南/西/北 结尾且基名不是独立车站 → 用基名
  （永城北 → 永城、黟县东 → 黟县）。这套规则与「线路是不是京沪」无关，换任何区间都成立。
- **站点档位（全部站 / 主要站 / 枢纽站）**：纵轴站点按「停靠车次 ÷ 本通道车次」自动分级 ——
  主要站 > 30%、枢纽站 > 70%，并设数量上限（主要站 ≤ 12、枢纽站 ≤ 7），首末站始终保留。
- **车型筛选（多选）**：可任意勾选车型，线型只分三类 —— 高铁 **G** 实线、动车 **D** / 城际 **C** 虚线、
  普速 **Z / T / K / 纯数字** 点线。
- **席别筛选**：默认关注「二等座 + 硬卧 + 硬座」，可改；**线条颜色 = 所选席别中「等级最低且当前有票」的那个**
  （避免「只有商务座有票却染成高价色」的误导），起价按所选席别有票的最低价计算。
- **余票 / 有票高亮**：可只看有票的车次，或把有票的车次高亮出来。
- **发车时间 / 票价 区间筛选**：侧栏双滑块，可只显示发车时刻落在某区间、或所选席别有任意一个票价落在某区间的车次。
- **中转联程查询**：点左侧站名即选中该站，刷新后**实时抓取（永远取最新）**「出发站 → 该站」
  与「该站 → 终到站」两程，就地叠加绘制，且原线路隐藏；退出即恢复。
  - 两程的**车型筛选互相独立**（第 1 程 / 第 2 程各一行按钮）。
  - 两程的**席别也分开选**（第 1 程 / 第 2 程各自勾选）。
  - 中转站若涉及多个实际车站，图上用 **6 种形状的点**区分（● ○ ■ □ ▲ △）并带行内图例；
    超过 6 个站时只列前 6 个，并在图例注明「…等 N 个站」。
  - **中转经停按需补全**：中转查询本身只取票价 + 余票（所以快），中间经停与直达走**同一套直连查询**
    （`czxx/queryByTrainNo`，`train_no` 直接取自票价载荷，省掉 MCP 那次「车次号 → 内部编号」解析，
    单趟 0.25 秒 vs 1.2 秒）；进入中转自动补一批（36 趟）当前可见车次，其余靠路由条上的
    「补全经停」按钮，结果并入共享 `stops.json`。并发数与直达共用「高级设置」里的那一档。
  - 车次明细表在联程模式下**按两程分段展示**，每段各自排序、各自计趟数。
- **搜索车次**：支持完整车次 / 纯数字 / 前缀，即时筛选运行图与明细表。
- **时间轴缩放**：滚轮缩放或以指针为锚点、拖动时间轴平移 / 缩放，双击重置；刻度随跨度自动切换。
- **经停抓取并发（高级设置）**：刷新栏下的「高级设置」可选 **串行 / 3 并行 / 6 并行**（默认 6，记在浏览器本地）。
  整车次经停一趟一个请求、一律直连 12306（不走 MCP，省掉「车次号 → 内部编号」那次多余请求），
  所以并发就是速度：实测 **393 趟首次抓取 20 秒**，而原来的「串行 + 每趟强制 sleep 3.5 秒」要 20 分钟量级；
  48 趟未缓存的中转经停补全 **1.9 秒**。被限流会立刻停下并保留已有进度，下次刷新接着补。

## 🚀 快速开始

### 方式一：双击启动（推荐）

直接双击根目录的 **`启动.bat`**。它会自动探测本机的 Python（3.10+），
起好本地服务并打开浏览器。关闭那个黑色窗口即停止服务。

### 方式二：命令行

```bash
# 默认 http://127.0.0.1:8765/
python scripts/start.py

# 指定端口
python scripts/start.py --port 9000

# 只起服务、不自动开浏览器
python scripts/start.py --no-browser

# 改默认乘车日期（也可以进页面后用顶部的日期选择器改）
python scripts/start.py --date 2026-10-01
```

打开浏览器访问 <http://127.0.0.1:8765/> 即可。

> 也可以直接用浏览器打开 `运行图原型.html`（`file://` 路径），此时看的是页面内置的数据快照；
> 「刷新数据 / 换线路 / 中转查询」需要本地服务在跑，所以建议走上面的启动方式。

## 🔌 数据来源与刷新

数据源默认 **`auto`**：先尝试 `mcp-server-12306`（`uvx` 拉起的 stdio 子进程，**只用于票价与余票**），
失败自动回退到内置 `urllib` 直连 12306 接口。**经停站一律直连**（见下）。

- 环境变量 `TRAIN_SOURCE=mcp|urllib|auto` 可强制指定；API 参数 `?source=` 亦可临时覆盖。
- 页面里的「刷新数据」按钮会重新抓取并写回 `data/viz_data.json`。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/data` | GET | 返回当前数据集 |
| `/api/refresh?date=YYYY-MM-DD&from=&to=&conc=6` | GET | 后台启动刷新；`from` / `to` 切换区间，`conc` 指定经停抓取并发（1/3/6） |
| `/api/status` | GET | 查询刷新进度与日志 |
| `/api/stations` | GET | 可选车站列表（3388 站名，供起终点选择器自动补全） |
| `/api/transfer?via=徐州&force=1` | GET | 查询经该站中转的两段车次（`force=1` 永远取最新，带缓存） |
| `/api/legstops` | POST | 中转经停增量补全（直连 12306，body 含 `date` / `conc` 与车次条目数组） |

## 🤖 开发与第三方开源软件

### 本项目的产出方式

本项目由 **DeepSeek V3.1** 以 *vibe coding*（自然语言驱动、AI 辅助迭代）方式辅助生成与打磨：
前端运行图、取数流水线、通道聚类、中转联程逻辑均由对话式迭代完成，人工负责架构决策与最终校验。

### 第三方开源软件

本项目在 runtime 以独立子进程方式调用以下开源组件：

| 组件 | 用途 | 许可证 | 与本仓库的关系 |
|---|---|---|---|
| [`mcp-server-12306`](https://github.com/drfccv/12306-mcp-server)（drfccv） | 12306 票价 / 余票查询（可选数据源） | MIT（含「禁止商用」附加条款） | 经 `uvx` 以**独立子进程**拉起；**经停站不走它**（直连更快，见下） |
| [`uv` / `uvx`](https://github.com/astral-sh/uv)（Astral） | 可选的 Python 包运行器 | MIT | 运行 MCP 服务 |

数据来源为 **12306 官方公开接口**（属数据而非软件）。

## ⚠️ 已知限制 / 说明

- **不写死任何线路**：通道划分用「中间城市集合」的 Jaccard 聚类，车站归并用 12306 官方车站表自带的
  「城市」字段。换成任意区间都成立。若某条走廊的命名不合口味，改 `data/channel_aliases.json` 即可
  （`names` 可手改，`keys` 是每次构建重算的特征站，仅供对照）。
- **经停站一律直连** `czxx/queryByTrainNo`，`train_no` 直接取自票价载荷 —— 走 MCP 时它得先发一次
  leftTicket 把「车次号」解析成内部编号，请求数翻倍、单趟 1.2 秒 vs 直连 0.25 秒。
  并发数在页面「高级设置」里选（串行 / 3 / 6，默认 6）；被限流会立刻停下并保留已有进度。
- **`queryByTrainNo` 返回该车次的全线经停**（不按 from / to 截断），所以程序会按本次查询的
  起终点在经停表里切区段。遇到**环线车次**（如 G8388 上海南环线）时，切出来的「区段」会绕一大圈，
  这是数据本身如此，不是错误。
- 实时余票来自 12306 公开接口，高频调用会被限流；遇限流会沿用上次快照并在页面明确标注「余票未知」，
  绝不拿别日的快照冒充。
- **站点档位阈值（30% / 70%）是经验值**：车次极少的通道（比如只有 3 趟）按比例算出来会接近 0，
  「主要站」会退化成该通道的全部站点 —— 规则使然。
- 数据仅供个人学习研究，实时购票请以 12306 官方为准。
- 第三方开源软件与许可证见上方「开发与第三方开源软件」一节；本仓库以 **MIT License** 发布
  （详见根目录 [`LICENSE`](./LICENSE)）。
